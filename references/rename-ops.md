# 改名类操作（纯改名／条目名／脚本·资源／目录／系列改号／编号库）

> 2026-09-25 从 SKILL.md 整节搬出，内容一条未删（各节保留原 `##` 标题）。
> 共同前提：改名＝**三个引用面**（反引号 `.md` 引用／`[文本](路径.md)` 链接／代码里的路径常量与文件名拼接）＋**名字住在哪**（文件名／标题／条目名）。

---

## 纯改名（basename 变化，脚本修不了）


只改名不换目录时，旧引用串在文件系统找不到目标 → fix 脚本按 basename 全库找唯一文件，但**新 basename 与旧引用串不同，脚本不会自动映射**——必须语义字符串替换：

1. 先 grep 引用面：`grep -rln "旧档名\.md"`——精确到 `.md` 后缀，避免误伤带角色/语境后缀的兄弟档（例：改「名场面与金句集.md」时子串不匹配「名场面与金句集-卡斯塔莉莉.md」，安全）
2. `git mv 旧名 新名` 保历史
3. 限本库目录全库 `perl -pi -e 's/旧档名\.md/新档名.md/g'` 替换
4. `fix_md_links.py --check` 复检；**顺手修替换后暴露的历史遗留断链**（实战：references/xxx 缺 `../` 前缀类 13 处，--fix 能自动补）
5. 改名若推翻旧规则（如「首角色无后缀」→「全库一律带角色语境后缀」）——落档规则文档/模板示例同步改，别留旧规则让后人照做
6. 复检时注意把「重名跳过」与「库外描述引用」（跨 skill 案例文件名）当排除项，别误修

## 条目改名（名字不住在文件名上：标题／条目名）


场景：改的是**一条东西的名字本身**（作品标题、篇名、条目名），不是某个 md 的 basename——名字散在 H1、目录名、索引表、别家 skill 的正文里，**没有一个 `git mv` 能一次带走**。与「纯改名」「系列改号」同族，区别是引用点不在文件系统里。

**先把引用点分三类**（判据只问一句：它是**指针**，还是**当时的记录**？）：

| 类 | 是什么 | 处置 |
|:--|:--|:--|
| ① **会自己跟上的** | 生成器 rebuild 出来的索引列 | 不用管，重建一次 |
| ② **指针**（手改） | H1／图片 alt／目录名／标题行／索引表的标题格／大纲文件名之外的抬头／**别家 skill 正文里点名它的句子** | 跟着新名走；索引格写成 `**新名**〔定名，旧名 旧名〕`——**别把旧名抹掉**（旧名是检索词） |
| ③ **当时的记录**（刻意不追改） | 历史档（会话存档、编号映射表、scratch 审读稿）、**档案键**（图库条目名、vision json 的目录名——索引与 json 都指着它） | **一个字不动**；在新档里写一行「旧名→新名」就够 |

**步骤**：

1. `git mv` **连目录一起改名**（目录名＝索引与 CLI 对齐的那一层）
2. 全仓扫残留，但**把 ③ 排掉**：`grep -rn "旧名" --include='*.md' --include='*.py' . | grep -v "session-archive\|编号映射\|scratch\|档案键目录名"`——剩下的必须清零，**残留清单本身就是验收证据**；不排掉历史档，会永远清不干净，还容易顺手把记录改坏（记录改写＝伪造当时的口径）
3. **重跑那个按目录名／ID 解析路径的 CLI**——解析走 glob 时，改名后不重跑就等于不知道它还认不认这个目录；跑一次几十秒，比事后被问「找不到」便宜
4. 条目自己的台账里补一节**定名**：记来路、判例、以及**被驳掉的方向**（不写，下一轮又往同一个词上撞）

## 脚本/资源改名：比 md 多三个引用面


改一个可执行件/资源的名字（不只是 md）时，反引号扫描覆盖不到的地方才是真坑：

1. **库外文档也在点名它**——别的 skill 的 references/ 里可能写着 `skills/chat-game-referee/scripts/mine.py`（排障笔记、设计说明、案例复盘）。**引用面扫描必须全仓跑，不是只扫本库**：`grep -rn "旧名" skills/ bin/ --include='*.md' --include='*.py'`，`skills/.archive/` 除外。
2. **运行时部署副本**——脚本常被拷到 `temp/` 之类的地方当部署件跑。改名当次就补一份新名、删掉旧名，再 `diff` 两端确认一字不差；旧副本留着既漂移又会被下次「拷最新」的逻辑漏掉。
3. **改名后重跑该库自测**——引用有没有接错，自测 30 秒就给答案，比肉眼翻强。收尾再全仓 grep 一次旧名，0 残留才算完。

替换顺序：先确认**新名不含旧名字串**（`mine.py` → `minesweeper.py` 不相交），确认了就能一次全局替换；若新名包含旧名（`x.md` → 「x-old.md」），必须长串优先逐条换，否则短串先吃掉长串、替换串被二次改写。

### 引用形态之三：代码里的拼接式路径常量（md 扫描器和字符串替换都抓不到）

反引号扫描与 markdown 链接扫描都只看 md；**脚本里的路径是拼出来的**，写法完全不同：

- `ROOT / "skills" / "writing" / "x" / "scripts" / "y.py"`（pathlib 除法链）
- `os.path.join(ROOT, "skills", "writing", "x")`

这类**每个路径段各自是一个独立字符串**——`replace("skills/writing/x/", …)` 在文件里根本匹配不到（那个串不存在），md 扫描器也看不见它。

- **扫描办法：对每个路径段单独 grep 一次**（`grep -rn '"writing"' skills/ --include='*.py'`），别只 grep 完整路径串。
- **收尾判据：把那些脚本真的跑一遍**。静态看「引用全改完了」不算数——实测就是这样的漏网引用在预提交门禁跑挂时才现形。有门禁拦着是运气，拦不下来的会变成下次才爆的坑。

## 目录改名：生成器管的链接之外，还有文档内自引用


改目录名时，**索引里那列由脚本 rebuild 出来的链接会自己跟上**（脚本按新目录名重新生成）——真正会漏的是**文档正文里的自引用**：每条文档里常有一行 `| **本文档位置** | \`<旧目录>/xx.md\` |` 这类。生成器只重写它自己产出的列，正文里的旧路径原地留着，日后按它找文件就断。

- 改名前先摸引用面，三种形态都 grep：`](旧目录/`、反引号 `\`旧目录/`、裸文件名
- 只改「文档里真出现过的旧形态」，别全局无脑替换（旧目录名可能同时是别的东西）
- 收尾用 `check_md_links.py` 全量 resolve，0 missing 才算完

## 编号文件库的整理（一总号多份 / 空号 / 批次分层）


按号排的档库长到几十份就会「看着乱」：一总号下挤着好几份、编号有空号、不同批次的档混在一个平面。四条做法：

1. **一总号多份 → 改子号，别改总号**：`110-挖料-*` 五份改成 `110-1 … 110-5`（按它本来就是一个系列的五个分册——给全新号会丢掉「同批」这层信息，也给引用面多造一层改动）。
2. **空号要在索引里说明，不是补号**：从没建过的号（如 `85–89`）在 INDEX 写「未建」；已并入他档的号（如 `107` → 节内 「改动单.md」）写明去向。不说明，后来人会把空号当「文件丢了」去考古。
3. **批次分层**：现行／历史（留原位，标「历史，勿照它开工」）／已归档（`git mv` 进 `归档-YYYY-MM/`，索引留一行）。判据只问一句：**现在还拿它当口径或施工依据吗？** 不用＋已被取代＝归档；拿不准留原位标历史。**归档 ≠ 删**。
4. **「节的账」不该住在过程层**：过程/核对档里若混着某节的改动单、落地记录，那就是它的正本——`git mv` 回该节目录（旧位置留一行去向），别让节的账寄住在按轮次排的文件夹里。

移动/改名/归档当天就循环跑一次链接体检（流程第 5 步「验证」，见 `../SKILL.md`）——这类整理是断链的最大来源。

## 系列改号（一篇一个号的库，整批换成另一套号）


线索：库里的号在外层被重编过（发布端重编、编号规则换过、本地号与线上号两套并存），要整批对齐；**或单篇发布时才发现线上号与本地建档用的号不一致**（增量版：只换两个号位、被占号位的那条顺延，其余不动）。**动手前读 `renumbering.md`**（逐条检查单＋增量版：权威源取值、映射表、改名、单趟替换、残留扫描、收稿比对、验收）。

四条先记住：

1. **权威源在库外，不在本地文档**——号的正本＝发布端那条（线上标题／主索引／生效中的总表）。本地目录名、skill 表、文件名都是副本，照副本改必错。
2. **「物理名字要不要一起改」先问用户拍**，别自己定。只改文档不改目录名 → 后来人按目录名找就找错；都改 → 动的是已发布条目的头字段（只动号，正文一字不动；首行仍是同一行、行数不变，文档里的 `行号引用` 不失效）。
3. **文档里的「代号」也是号**：锚点表拿号当代号（`P13:L7`）时，代号本身会变成错号——一起换，并把全库引用点同步（时间线、对照表、结论段都会引它）。
4. **抽出号序列的条目要给固定代码**（如 `SP1`／`Ep01`）写进索引与沿革表，否则旧号里的「06」会被后人当成正式第 6 篇读。
5. **改完不是终点**：之后**新写的每一份文件**都要回扫旧号（新文档才是新旧混用的高发地），提到旧号一律带「旧号」二字；同数字前缀的旧件当场处置——别留给「按文件名取该号大纲」那类 CLI 去赌排序。

配套：**历史档（日记、对谈存档、旧稿原文）一律不动**——改它＝把当时的记录伪造成现在的口径；旧号只在沿革表／口径注里留对照。**别漏裸号**：子项目文档里的裸号可能指另一套序列（如长篇的节号），只改带前缀的引用，并在那些文档顶部加一句「两种号不同源」。

## 约定名加归属后缀（同名同质文件消撞）

**场景**：同一个文件名在多个同级目录里各一份（`community/<帖>/整理稿.md` ×3、「楼主内容.md」 ×3、`sources/*/00-references角色设定.md` ×16）——引用写裸名时机器无法判「哪一份」，只能逐条改叙述。用户要的是**从根上消撞**（让 basename 唯一）。

**先分清「产物」与「格式契约」，只有产物能改名**——这是本节最容易走反的一步：

| 类 | 判据 | 例 | 处置 |
|:--|:--|:--|:--|
| **产物** | 同一用途、每个目录内容各不同；没有任何规范/工具按名字识别它 | `整理稿`／`楼主内容`（每帖一份）、`sources/*/00-references角色设定`（每来源一份）、`staff-roll/ms1–ms5`（每代一份） | 加归属后缀，`<名>-<归属>.md` |
| **格式契约** | 名字由格式规范或工具约定，换名就不成格式 | 「IDENTITY.md」／「persona-soul.md」／「AGENTS.md」（人设包三件套，「PERSONA-FORMAT.md」 定义的）、「INDEX.md」、「README.md」、「_template.md」 | **不改名**——跨目录同名是设计，引用写全路径或用「」叙述 |

同一 skill 内两个目录各一份、互相不是同一用途时（「games/ms1.md」 游戏档 vs 「sources/staff-roll/ms1.md」 名单档），**只给次要那份加领域后缀**（「ms1-staff.md」），主档保持原名——两边都改等于给主入口多造一层改动。

**这是改契约，动之前说清代价并等用户拍**：产物名也常被 CLI／脚本写死（`sssj_community.py` 直接 `os.path.join(path, "整理稿.md")`），改名会连带改工具。

**顺序不能反——先加解析，再改名**：

1. **在读取端加兼容解析**（新名优先、旧名兜底），旧帖不迁移也照读：
   ```python
   def post_file(ppath, base):
       """优先 <base>-<目录名>.md，回退旧名 <base>.md"""
       d = os.path.basename(os.path.normpath(ppath))
       cand = os.path.join(ppath, f"{base}-{d}.md")
       return cand if os.path.exists(cand) else os.path.join(ppath, f"{base}.md")
   ```
   把脚本里所有硬编码 `os.path.join(path, "整理稿.md")` 换成 `post_file(path, "整理稿")`；相邻脚本（`community_meta_scan.py` 这类）也要各改各的。
2. **`git mv` 改名**：`<名>.md` → `<名>-<归属>.md`，归属取**目录名全称**（带日期，避免同名帖再撞）。
3. **同步引用**：目录内的裸名引用按**所在帖**补后缀；跨帖引用（`../<别的帖>/楼主内容.md`）补的是**目标帖**的后缀，不是当前帖——最容易改错的一条。帖外文件（SKILL.md／CLI 文档）按前文给出的路径判断归属。
4. **跑 CLI 实测**：`list` 能列标题、`entry` 能取条目——只验文件存在不算，读原文那条路径才是真契约。
5. `fix_md_links --check` ＋ `mdcheck --root <库根>`（后者可选） 双跑回零；`workspace/tmp/` 里的旧副本不算残留，别去改。

**向后兼容是纪律**：解析器留着旧名兜底，将来有人按老约定新建 `<名>.md` 也不会崩——第 1 步做完就可以安全改名，不必一次性迁完全库。
