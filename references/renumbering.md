# 系列改号 · 逐条检查单

> 什么时候读：一套号要换成另一套号（发布端重编、本地跟线上、两套号并成一套）。先读完再动文件。

## 铁律

1. **权威源在库外**：号的正本＝发布端那条（线上标题／主索引）。本地目录名、skill 的表、大纲文件名全是副本——照副本改必错。
2. **范围先问用户拍**：「要不要连已发布条目的物理目录名／首行标题／元数据一起改」。摆情况＋推荐选项，方向由他定，别自己定完再问「行不行」。
3. **先落映射表再动手**：旧号 → 新号 ＋ 标题 ＋ 对外号，成一页落档——它同时是施工单和事后对照表。
4. **历史档不动**：日记、对谈存档、旧稿原文保持原样；旧号只写在沿革表／口径注里做对照。

## 检查单

1. **取值**：先拿权威源把「新号 ↔ 标题 ↔ 对外号」整表取回来（一次 API 或一条 `status` 命令），别一处处手敲。
2. **列实体**：目录名、每个目录内的文件名、索引／大纲文件名、待发布稿目录，逐个过映射表，一个都别漏。
3. **改名（保历史）**：`git mv` 或 `mv` + `git add -A <顶层目录>`——改名会产出成堆 D＋未跟踪对，整体收才看得出是重命名而非删＋建。
4. **同步头字段**：正文首行标题 ＋ 元数据里的 title 换成权威源现标题。**只动号，正文一字不动**——首行仍是同一行、行数不变，文档里的行号引用不会失效（改完抽查一条对得上）。⚠️ **别顺手重新抓取/重新生成这份文件**：权威源的发布头（发布时间·链接·【前排说明】块）是**会插行**的，一插行号整体移位 → 拿行号当基准的引用表（锚点表、引文索引）静默失效。**已落盘且被行号引用的文件只许「同一行替换」，不许重抓**；非重抓不可时，先重建那份行号表再动。
5. **批量替换＝单趟 token 映射**：一个 `re.sub` 带 alternation 同时处理「前缀号（含 `／` 链）」「号 ＋ 行号引用」「成对号」，repl 里查表。**别连跑多个 `re.sub`**（会把已映射的值再映射一次）。改前 `grep -c` 数一遍，改完再数一遍。
6. **扫残留**：动手前先 `grep -c` 数一遍命中处数（＝要同步的文件数）：**同一张号表常同时住在 skill 表／档案索引／子项目文档／脚本里的硬编码清单**，只改一处＝两套口径当场打架，半成品会被一眼看穿。改完再 grep 旧号＋标题的组合、旧区间写法、「两套编号／本地 ＮＮ」这类说法——命中应为 0（沿革表与口径注除外）。
7. **收稿比对**（若新号对应的条目已发布）：把权威源那份拉下来，与本地稿**逐行**比（先剥掉标题行／图行／发布头／前言块，比非空行表＋字数），有差按「以线上为准」记账，别默默以本地为准。
8. **验收**：目录名全是新号；状态命令不再报「有对外号没本地稿」；改过号的稿跑一次自带体检命令确认路径解析还通。
9. **落账**：映射表加「执行记录」——做了什么／验收数字／**刻意没动什么**；随后 commit（含被点名的脚本与索引同步改动）。

## 增量版：只换一两个号位（发布号 ≠ 写稿号）

线索不一样：**不是整批重编，而是发布时才发现「线上那条用的号」与本地建档用的号不一致**——线上占掉的那个号位，本地原先留给的是另一条。

**先定是哪一形态，这步别自己拍**：**顺延**＝被占号位那条往后挪、其后不动；**互换**＝两条对调。用户说「改成 `NN`，把原有的 `NN` 换到 `MM`」＝**互换**；只说「发布号是 `NN`」多半是顺延。分不清就问（写错形态，后来人会按错的那套推全库）。

- **权威源仍是线上那条**；先**查明冲突范围**再问用户：三处对照（线上列表、本地 `list`、索引表的未发布段）。**被占号位的那条怎么办要用户拍**（顺延到下一个空位／撤下不编号／其后号动不动）——这是改默认，属 T1，别自己排。给 2–3 个选项、推荐项放第一个、每个写清后果。
- 没有全量映射表可落，**改的只是「同一条目在十几个文件里的自称」**：实体名（大纲／草稿／暂存目录）、过程档正文、以及全部现行口径的引用点。**每一处都要人判**——哪处是「现行自称」该跟着走，哪处是「当时的记录」不许动；整库无脑字符串替换必错。
- **暂存目录并入正式目录**：把里面的过程档（逻辑链单之类）`git mv` 进带对外号的新目录，末尾补一节「发布核对」（新号／diff 结论／收档命令／原图在哪个档案库）；旧目录连同重复正文一起清掉——留两份正文＝两套口径。
- **收稿后先做逐行 diff**（剥掉标题行／图行／发布头／前言块，比非空行表＋字数）：差异通常只该有 H1 的符号与发布头；**正文只要有一处差异就单独记账**——用户可能在发布端有意删句，别自动改回去。

### 这一族最易漏的引用面：文档里的**命令参数**

过程档（逻辑链单、体检记录）里常写着 `bin/<cli> expand 16`、`bin/<cli> sample 16` 这类**示例命令**——号在那儿是**参数**，不是文件名。改号后这些例子会**静默指向另一条**，后人照着跑就跑到别人头上。

- 改号时逐条扫命令字面量：`grep -rn "bin/[a-z-]* [0-9]" <库目录>`，与号表／新号一起换。
- 同理，任何「按号取件」的写法（`new <号>`、`plan <号> --write`、按号排序取大纲）都在引用面里。

### 互换版专章（两条对调）

两条号位互相顶替，比顺延多一层陷阱：**「裸号当成对换」的两趟替换会自撞**。

1. **先 `mv` 后改字**：大纲 NN-slug.md、drafts/NN-过程料.md（NN＝真实号位）、条目的物理目录名先改（用 `mv`／`git mv`，提交时 git 报 `R` 才叫改名；「删＋建」会把历史切断）——改完再扫内容，此时扫出来的文件名已经是新号。
2. **一次只走一个方向的「旧串 → 新串」，锚点必须是唯一长串**（整句、整行表格行）。**绝不能先裸替换 `19`→`16` 再 `16`→`19`**——第二趟会把第一趟刚写好的新号又换回去（一步双跳）。短锚能匹配到多处时，一律换成带上下文的整句。
3. **这些数字不是号，别碰**：对外号／cv 号／日期／**表格的行序号**（候选表 `| 16 | 某条候选 |`——行序撞上新号是常态）／条数与篇数（「19 条候选」「现 19 篇」）／相邻资料库的块号（`v16`／`v19` 这类老素材块 ID）／图库条目号（`048`、`036`）。
4. **跟着条目走的映射一起换**：图库条目 ↔ 条目、候选池表、提案／对照表、设定档案里的出处标注（表格里单占一格的那个号）。
5. **改完回读**：状态命令认出新目录且无异常 → 再 grep「旧号＋标题」的组合形态确认零残留 → **顺手回读每个改过的区块**。这条不是形式：锚点若不是唯一整行，替换会把它和相邻行粘成一行（实测把「文集入口」那行和下一行粘在一起）；索引里的字段也常与正本脱节（一个字段挂了多轮没人发现，就是因为没回读）。
6. **落账**：沿革里写明是「顺延」还是「互换」，再留一句「发布后若线上号与之不符，按发布号≠写稿号再改一次」。

## 坑

- **批量替换要「全中才写盘」**：一批精确字符串替换写成原子操作——**逐条断言命中数＝1**，任一条没命中就整批中止、不写文件（文件仍干净，查清原文再重跑）。凭记忆拼的 `old_string` 会一条都不中：加粗标记 `**` 可能包着比你以为的更长的片段（实测 old 写成 `**16 处超载**`，原文实际是 `**16 处超载 ＋ 5 处…**`）——写之前先 `repr()` 看那一行的真实内容。
- **体检数字要判归属**：改完后跑体检报出的问题，**先确认不是自己引入的**（改名前跑一次留基线，或逐条看是否碰过那个文件）——存量断链与老毛病混在一起，会把「本轮零新增」误读成「我改坏了」。
- **状态命令只认对外号**：未发布的暂存目录若命名成无号形态，既不入「本地有」也不报缺 → 已发布条目必须收一次稿，别指望暂存目录顶替存档。
- **裸号会串味**：子项目文档里的裸号可能是**另一套序列**（如长篇的节号）而不是本库的号。只改带前缀的引用，并在那些文档顶部加一句口径注说明两者不同源。
- **改完还会滑回去（高发）**：改号当天及之后写**新文档**时最容易把旧号带出来——写新大纲、新台账、新结论段时，脑子里活跃的仍是刚整理完的那套旧号（血账：统一当天写新篇的七环单，又把不占号的字母篇写成「特别篇 06」）。两条对策：① **每产出一份新文件就回扫一次**（查旧号＋标题的组合、以及「特别篇 0X」「本地 1X」这类形态）；② **任何提到旧号的地方都加「旧号」二字**（沿革表、口径注、弃案说明）——不带标记的旧号会被后来人当现行号读。
- **别让两份东西共用同一数字前缀**：按文件名排序取件的小工具（生成器、CLI 的「取该号大纲」）会取错——同号两版要当场处置（移去素材库或改号），别「等以后再说」。
- **按名字写死路径的脚本会静默失联**：改名后跑一次该库的自测／体检（或先 grep 脚本里的旧名），改成按 ID／目录名通配定位＋根目录自推。
- **不要为了「统一」把历史记录也改了**：改历史是造假；新旧对照写在沿革表一处就够。
