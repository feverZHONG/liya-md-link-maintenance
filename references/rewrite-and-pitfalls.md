# 批量重写与坑（三条硬规矩／踩坑／实战案例）

> 2026-09-25 从 SKILL.md 整节搬出，内容一条未删。

---

## 坑


- **`fix_md_links.py` 的 `--root` 决定「什么算跨库引用」，指错就是一片假阳性**：库内若统一用「库根相对」反引号引用（如某资料库全库写 `skills/<资料库>-archive/references/生日内容登记.md`、`characters/…`、`故事设定集/…`），跑校验必须 `--root <库根>`；默认按仓库根（`<库根>`）解析会把它们全报成断链（2026-09-12 实测：几十条假阳性，换 `--root` 后只剩裸 basename 简称类）。**剩下的命中才要人判断**（裸文件名简称、命名模板、库外描述）。
- **目录引用（非 md 文件）不会被扫描**：如 baike-basics.md 里的 `types/` 要手动改 `../types/`
- **重名 basename 导致自动修复跳过**：case-writing.md 移入 cases/ 后内部 「cases/INDEX.md」 应改 「INDEX.md」，脚本因 INDEX.md 重名跳过 → 手动修
- **依赖树验证要真扫一遍**：修复后用脚本全量核对（排除项列表过滤），比肉眼靠谱
- **新建的 INDEX 写在子目录里，表内路径要按它自己的位置写**：从母 README 搬一张长表进 「某夹/INDEX.md」 时，若原样保留「「某夹/xx.md」」这种**相对库根**的写法，一张表就能断 60+ 处（实测 63 行表 = 63 处断链）。搬表后当天跑一次 `fix_md_links.py --fix` + `bin/mdcheck` 复检。
- 先查 git 状态再动手：重构只 add 自己动的目录，别把别人未提交的变更卷进来
- **在表格行之间插说明块，会把表格截断**：md 表格是「表头＋分隔行＋连续行」一整块，中间插一个引用块（`>`）或普通段落，**后半张表就掉出表格**——渲染成散行，解析器数表行也会少掉一半（实测：在一张十几行的表中间加一条更正说明，后半五行全部出表）。**说明块一律放表尾或表外**；表格加注在表后另起一段。已经插进去了：把块删掉、行接回表格，注解放到表后（并在那儿写一句「原表里误记了什么」，别把更正信息一起删了）。

## 批量重写正文：三条硬规矩（重写 md 内容的脚本必读）


1. **解析顶层章节要按白名单匹配，不能见到 `## ` 就当章节边界**——被嵌进来的原始文本（vision 输出、聊天记录、别的文档）自带 `##` 标题，会把嵌入内容从第一行起整段切掉。做法：只把「已知章节名（可带括号后缀）」当边界，其余 `##` 算当前章节的正文。
2. **收尾必须跑两遍验证幂等**：同一份输入跑两次，输出逐字节相同才算过。不幂等的常见来源：每轮都会重新拼一次的头尾空行、被过滤后又长回来的空行——统一做一次空行归一（`\n{3,}` → `\n\n`）和各段首尾去空。
3. **一套号换另一套号时，映射必须在「单趟」里完成**：一个 `re.sub` 带 alternation 同时吃下所有待改形态（前缀号＋号链、号＋行号引用、成对号），repl 里查表。**别连着跑多个 `re.sub`**——前一趟把 `10→08`，后一趟又把刚写好的 `08→06`，一步双跳，整份文档被映射两遍（实测：68 处引用全错）。动手前先 `grep -c` 数一遍命中数，改完再数一遍。

另外：破坏性重写一律 **默认预览、`--now` 才落盘**；批量前先整一件给人看过再铺开（格式没点头就开跑，错的是一整批）。

## 实战案例


2026-09-19 某长篇项目废案库分层（63 → 5 份在根）：`git mv` 按四类分入 `过程稿/{加厚单,诊断修法,追溯旧案,核对}/`（含四处**编号撞号**：两个 `22-`／两个 `23-`，靠移进不同夹分开）→ `fix_md_links.py --fix` 98 处 → 搬出 README 那张 63 行长表成 「过程稿/INDEX.md」 又断 63 处 → 再修 → **`mdcheck`（可选工具）问题总数 0／`check_md_links.py` 0」。另一收获：两个检查器对「库根相对引用」的处理不同——先用 fix 脚本（`--root` 默认仓库根）扫干净，再用 mdcheck 复核，两者都干净才算完。

2026-08-31 enneagram-notes references/ 分目录重构：18 个平铺 md 分 5 目录（theory/label-systems/psych/methodology/clusters），355 处引用验证，真正断链清零，顺带修了 10 处历史遗留断链（subtype 前缀/b-fuchuan 悬空引用）。

2026-09-05 某资料库多轮搬家 + 人物拆分（同日连做四轮）：衍生→子夹化→移外层改名→撤角色层平铺为故事设定集 + 群像合并档拆 7 独立人物档。要点：每轮都按「语义重写相对路径（{pre} 按文件深度）+ 收尾全量 resolve 校验 0 missing」闭环，最后整体轮才暴露历史遗漏（整理档移入子目录后裸正文链接缺 `../正文/` 前缀）——**每轮搬家都该跑一次全量校验，别攒到最后**；删合并档前先 grep 旧档名引用面，改档名批次内全库替换完再删。
