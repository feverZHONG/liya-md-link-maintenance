# 搬家类操作（层级整体搬家／搬节拆档）

> 2026-09-25 从 SKILL.md 整节搬出，内容一条未删。
> 适用：目录层级整体上移/下移一层；文件不动但内容块在文件之间搬（锚点照样会断）。

---

## 深度变化的整体搬家（整体上移/下移一层）


场景：整个子库平行移动、层数 ±1（实战：`stories/<角色>/衍生/<层>/` → 顶层 `设定集/<层>/`）。此时所有「指向库外命名空间」的相对路径都变——**fix 脚本只修「解析不存在的断链」，深度错位若恰好解析到另一个存在（但错误）的位置不会报**，必须语义重写：

1. 先物理移动（`git mv` 或 `mv` + `git add -A`——git 自动识别 rename）
2. 对每个文件算到仓库根的 `../` 跳数 `{pre}`（如 子库根文件=2 跳、层子夹内=3 跳；整体上移一层则全体 -1）
3. 正则把「已知目标命名空间」（正文/整理/characters/references/stories）前任意形态的 `../` 前缀整体替换为 `{pre}`——不猜旧路径写法，按语义统一重写
4. 内部互链若子夹相对关系没变（`../人物/x.md`）则不动；只动跨出子库的引用
5. 收尾必跑全量链接目标存在性校验（`](相对路径.md)` 逐个 resolve），0 missing 才算完

坑：

- **同目录文件间的裸链接最易漏**：文件移入子目录后指向同层目标的裸文件名（`](兽耳故事_x.md)`）需要加 `../` 前缀，批量重写常漏——靠收尾全量校验暴露
- **移动前先清 untracked 残留**（文件管理器重命名副本如 「INDEX (2).md」）：`git mv` 整个目录会把它卷走，git 状态变 AD 乱局 → `git reset` + `rm` + `git add -A` 重来
- **反引号描述里的跨 skill 路径**（如 `enneagram-notes references/cases/...`）不算断链——是库外描述文字，别去解析

## 搬节/拆档：内容块重构的引用面（文件不动，锚点也会断）


把某个文件里的**节**搬走、重排、去重，同样会断引用——此时引用点住在**别的文件里**，按「文件名 + 节号」定位，文件系统扫描一个都报不出来。

### 1. 动手前先做引用面普查（含脚本里的文案）

```bash
grep -rn "<库名>|§<节号模式>|旧节标题" --include='*.md' --include='*.py' skills/ workspace/
```

- **脚本里的引用最易漏**：CLI 的报错文案与帮助文本常写「判据出处：`skills/short-stories-liya/references/p0-core.md` §四·七」——改节号断的是**运行时的可追溯性**（出错时按图索骥找不到）。
- **结论：文件名不动、被外部引用的节号不动**，只做「**归位**」：把追加造成的乱序按序排好（夹在章节中间的「五、六」挪到末尾、无标题的段落补上标题），**不重编**。重编要同步改所有引用方，收益几乎不值；编号保留还能让一次重构不必变成一次全库改名。

### 2. 判据 vs 案例：搬什么、留什么

| 层次 | 做什么 | 判据 |
|:--|:--|:--|
| 跨文件去重（最肥） | 见 `ref-forms.md` 的「内容重复也是引用链问题：单点真源 + 指针」 | 措辞不同、语义同一也算重复 |
| 案例出档 | 血账／实测数字／session 实录／成段示范文／候选菜单 → 独立档 | 正文留一行指针；案例档题头写「规矩在 X，这里装『这条规矩是怎么来的』」 |
| 单文件压字（收益最小、风险最高） | 压措辞、并短节 | 放最后，只压叙述不压判据 |

**先量覆盖率，再决定搬还是只压缩**（别按「这行很长」下手）：对每条超长行取 12 字窗口，比对同一个 skill 的全部 references 文本，算有多少窗口已经躺在 refs 里。

| 覆盖率 | 含义 | 动作 |
|:--|:--|:--|
| 1–15% | 判例确实没进 refs，真「可搬未搬」 | 搬（拆薄主力就是这类） |
| ≥50% | 细节已在 ref 里 | **只缩短正文那一行**、留指针；再搬＝ref 里存两份 |

不量的后果两个方向都有：把重复内容搬成两份，或放过真正肥胖的部分。抽样看五行靠不住——同一条目里往往既有一句判据（搬不动）又有三个实例（全能搬）。

**两类「行数高但不该拆」**（先看再动手，否则拆完更难用）：

- **枢纽型**：读它的第一屏就是在选路线（多模块分流表），模块全搬走只会让每次任务多开一个文件再读回来。判据「这一屏是不是选路用的」，是 → 留。
- **表格撑出来的行数**：两百多行却只有六千多字符（收录清单、字段表）——每行十几个字，砍不动也没东西可砍，先看字符数再决定。

> **spec 驱动工具搬条目的定位坑**：`skill_thin.py` 的 `moves[].match` 是按 `l.strip().startswith(match)` 比的，**不能带前导空格**——缩进子条目（`  · **…**`）照拄原文连缩进写进 `match` 会命中 0 处、直接报「逐条定位失败（0 处）」。`match` 取 strip 后的前缀，`keep` 仍带缩进（替换的是整行，缩进别丢）。

- **判据**留正文：量化阈值、禁令（零容忍／必须归零）、修法路径（「要么…要么…」）、判断问句。
- 判据句里的**例句表**是判据的一部分（读者靠它对照），留；同一内容的**成段示范文**可以搬。

### 3. 内容搬迁的守恒校验（对应文件搬迁的断链扫描）

跑「原文每行（归一化去空白后 ≥25 字）必须出现在 `新文件 ∪ 同库全部档`」。

- **编号标签双向对账**：正文搬进 refs 后常按「详案 XXn」建小节标题——收尾用脚本把 SKILL.md 里出现的每个编号抽出来，逐一确认 refs 里真有 `### XXn · ` 标题。**改了编号没回头改指针**（或两个同主题各编一个号）是这步最易漏的欠账，工具的体积校验看不出来。
- **工具自动生成的小节标题要过一眼**：`### <标签> · <加粗标题前 40 字>` 会把标题从中间剃断（`…落在某个 v`）；同主题二次拆薄时新标签还会撞上旧标签（`IR15 · git 收尾总则` 挨着 `IR7 · git 收尾总则`）——落盘后 `grep '^### '` 逐条扫：截断的补全，撞主题的退成子标签（`IR7b`），**同时把 SKILL.md 里的指针改过去**。
- **新建的 ref 必须挂进 SKILL.md 的引用表**：搬运只在正文留一句「见 `references/x.md`」时，索引表没这一行下一轮就成孤儿；结构表或手册索引至少补一行。
- **对重写型文件这报告会大面积假报**（措辞一改就「未命中」）——它是**待判清单不是待补清单**：逐条问「这是有意压缩，还是内容丢了」，真丢的才回填。
- 再抽查「命令与路径字面量」（`bin/*`、目录名、文件名）是否仍在某处——这类丢失不体现在措辞比对里。
- **不为体积目标砍判据**：判据密度高的档压不动（判据档实测只降一成多，案例型能降六到八成）。计划里写「判据一条不砍，只合并与搬位」，体积是结果不是目标。

## 跨库搬家：把内容搬出技能库（去归档区）

场景：内容没错、也不是重复，只是**不该住在库里**——文档自己就承认它过期了（「已发布篇的骨架只剩存档价值」「旧号目不追改」这类写法）。技能库只装「现在要用的」，这类搬去 `workspace/records/<主题>-归档/`。

1. **搬之前先落计划**：搬哪些、搬去哪、哪一份留作样板（搬走那批里若有「现行格式样板」，就在索引里把它的新路径写成入口）。
2. **每份加一行归档题头**：原在哪、为什么搬、当前入口在哪。没这一行，半年后没人知道它为什么躺在那儿。
3. **引用面比库内搬家宽一倍**：旧路径会同时出现在①文档相对引用（含目录级 `.../drafts/`、`../NN-x.md` 这类写法）②**CLI 脚本的运行时文案**③**跨 skill 引用**。搬完先全库 grep 一次三个面，再跑链接检查。
4. **mdcheck 的问题数会先涨后落**：搬走文件会把**原本能解析的引用**变成断链（实测一轮 64 → 81），修完引用才回到基线以下（→ 56）。**目标是「不高于整理前基线」**，不是清零（存量断链不清）。
5. **引用统一改「新落点＋原名」**：「outlines/14-x.md」 → `workspace/records/<主题>-归档/14-x.md`；跨 skill 里的节号引用照旧保留节号（锚点不重编号）。

⚠️ 「只剩存档价值」≠「可以删」——已发布作品的大纲与过程料属于**可查的历史**，只是换住处。

## 内容搬进 `references/` 后，相对基准跟着变（最容易漏的一层）

从 SKILL.md 往 `references/` 搬正文时，**搬过去的那段话是按「skill 根」写的**：里面的 `references/xxx.md` 到了 refs 内部就差一层，正确写法是裸名 `xxx.md`。工具会把它报成「可修」（「references/x.md -> x.md」）。

- **判据**：搬完先不加 `--fix`、直接 `--check`，看「可修」栏是不是**全部落在本 skill 的 references/ 内**——是就只是这一层基准问题，不是内容误导；逐条改成裸名再复跑归零。
- **同源的第二层**：搬进更深一层子目录要加 `../`（见上节「深度变化的整体搬家」）；搬进 `templates/`、`scripts/` 同理。
- **别用批量替换把全库的 `references/` 都剥掉**：SKILL.md 与子目录文档里的 `references/x.md` 是对的，只有**新家就在 refs 里**的那些行需要改；按「哪些行是本轮搬过去的」定位，别按字符串全体匹配。

### 5b. 表格型源文件：整行搬，别切单元格

场景：源档只有百来行，但其中一张表的每格都是一篇小判据（命令＋参数＋坑），单表吃掉全档 60–80% 字符——接口手册类最典型（几十行表格塞两万字符）。

- **按 `|` 切单元格必丢内容**：单元格里的反引号代码常带裸管道（`curl a \| python3`），split 会在那里断开——多出来的那截被当成新列丢掉，**整行静默截断，工具不报错**。一次实测 29 行丢 6 行。
- **按整行搬**：ref 里每行写成 `## <场景>` ＋ 代码块包住原表格行；主档换三列索引「场景 ｜ 工具 ｜ 文件」，工具名从原行正则提取（`([\w\-]+\.py)`、`(bin/[\w\-]+)`，都不中就看是不是裸接口）。
- **守恒校验按整行、不按格**：`re.sub(r'\s+','',原行) in 去空白后的 refs`。逐格比对会因单元格里的 `**` 与反引号全假报（归一化只做了一边就更乱）。
- **别用整段切片替换（`lines[s:e] = ...`）**：表段里夹着的非表格行——加粗小标题、前置警告（「cookie 前置」「Playwright 版本软链」这类）——会连带被吞。实测一次吞掉一条根因纠错和一条前置警告，只有拿原文件逐行比对才抓出来。**改完立刻跑「原文件每行 ≥25 字必须出现在新档 ∪ refs」**。
- **落盘先看 ref 体积合不合常识**：四档各 2–9K 字符正常；某档只有几百字符＝那一段搬漏了。

### 5. 整节搬出到 refs：编号不动 ＋ 索引表

场景：节标题是 `## 八、…` 这种中文编号，正文散着「按 §八 留痕」「见 §十五」（四百多行的档里二十来处）。两条路，选后者：

- 逐处把「§N」改成 refs 路径——二十处手改必漏，漏掉就是断锚，而且 **`mdcheck` 与 `fix_md_links` 都查不出来**（它们只查文件存在性与编号跳号）。
- **编号不动**：搬走的节在 ref 里保留原 `## N、标题`；SKILL.md 顶部插一张「节次 → 文件」表 ＋ 一句「正文里的 §N 指节次编号，本文件没有的按上表去对应文件找同一编号」。走 `skill_thin.py` 时全部 `section_moves` 取 `mode: verbatim` ＋ `keep_text: ""`（整节搬走、正文不留占位），索引表落盘后用 patch 插进正文开头。

验收脚本（`断锚` 必须为空，另加一条「原文件每行 ≥25 字都在池子里」的守恒兜底）：

```python
import re, glob
new = open('SKILL.md', encoding='utf-8').read()
pool = new + '\n' + '\n'.join(open(p, encoding='utf-8').read() for p in glob.glob('references/*.md'))
refs = {m.group(1) for m in re.finditer(r'§([一二三四五六七八九十]+)', pool)}
have = {m.group(1) for m in re.finditer(r'^## ([一二三四五六七八九十]+)、', pool, re.M)}
print('断锚:', sorted(refs - have))
```

**搬前先提交一次基线**：`sk verify` 以 `HEAD` 为基线，工作区里原有的未提交改动会混进 MISS，分不清是丢的还是本来就没有。先 `git add <该 skill> && git commit`（一次 chore 基线提交），此后的 MISS 才只可能来自本轮有意的指针改写——那种按条数写进提交说明即可，别去「修」。

### 4. 并行写者纪律

- 多文件同时改时**按文件切分工**，同一文件同一时刻只能有一个写者；**跨文件搬运**（A 的某节并入 B）要等两个文件的写者都收手再做，否则后写者覆盖先写者。
- 收到「文件被其他会话／兄弟代理改过」告警时先核实再继续，不必停：

```bash
git show HEAD:<仓库相对路径> > /tmp/head.md
diff -q /tmp/head.md <动手前的备份>/<file>   # 一致 → 你读到的就是 HEAD 版，没覆盖未提交改动
```

- 动手前**整目录备份**（`cp -r`）——回退与上面的告警核实都靠它。
