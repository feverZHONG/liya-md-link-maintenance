# 引用形态与纪律（grep 取样／markdown 链接／跨 skill／占位名／单点真源／稳定 ID）

> 2026-09-25 从 SKILL.md 整节搬出，内容一条未删。
> 收尾前对着本档过一遍：这里每一条都是「扫描器看不见、只有人知道」的引用面。

---

## ⚠️ 全仓 grep 的取样范围：先排掉非目标目录


「引用面扫描必须全仓跑」不等于无脑 `grep -r .`——大仓里有体积失控的非文档目录，会把输出淹掉，真正要找的命中反被挤没。实测：`skills/.hub/index-cache/` 那份上游技能索引是**十万条、几十 MB 的单行 JSON**，任何 `grep -r skills/` 都会把它整份吞进输出（一次炸出数千万字符，工具侧只能截断）。

- 扫引用一律 `--include='*.md' --include='*.py' --include='*.sh'` 限定后缀，并显式避开 `skills/.hub/`、`skills/.archive/`、`skills/.curator_backups/`、`node_modules`
- 更稳的输入源是 `git ls-files <目录>`——只给被跟踪的文件，天然排掉这些
- **判别信号**：命中里出现 `"trust_level"`、`"identifier"`、`"source": "official"` 这类字段＝扫到索引缓存了，立刻收窄范围重扫

## 引用形态之二：markdown 链接 `[文本](路径.md)`（收尾必扫，脚本只查不修）


`fix_md_links.py` 只扫**反引号** `.md` 引用；库里正文还大量用另一种形态：`[文本](相对路径.md)`。它不在前者的覆盖面里，**每写完一批新档/新链接都要单独全校一遍**：

```bash
python3 skills/md-link-maintenance/scripts/check_md_links.py skills/<skill> [更多目录]
```

脚本遍历所有 md → 抓 `[文本](目标)` → 跳过 `http/#/mailto` → 按当前文件所在目录 resolve → 报「解析不存在」的目标；**只查不修**（目标该改成什么要人判断：改名、占位符、库外描述各不相同）。深度变化搬家那节说的「全量 resolve 校验 0 missing」就用它落地。

实战（2026-09-12 一个资料库 + 一个写作 skill，203 个 md）——4 处断链，四类病各一例：

| 病 | 实例 | 怎么修 |
|:--|:--|:--|
| 目标档改过名，链接没跟 | 指向 「官网动态登记-归档2022-2024.md」，实际是 「-2022-2025.md」 | 改成真名（顺带全库 grep 旧名，清残留） |
| 相对路径层级错 | 子目录里的 `../故事设定集/…` 少一级（应 `../../`） | 按 `os.path.relpath` 重算，**别手数跳数**（同批新写的链接最容易犯；上几十处必脚本化，做法见下节） |
| 占位符当链接 | `[04 整理](…)` 从来没填过目标 | 补真链，或改纯文本（看邻居行的惯例） |
| 同段注重复粘贴（一旧一新） | 归档拆分注存在两条，一条还写着旧年份 | 删旧的，别让两版并存 |

## 跨 skill 引用要写对路径，别当「库外描述」混过去


同一个引用，两个检查器态度不同：`fix_md_links.py` 把 `skills/<别家 skill>/...` 这类当「库外描述」跳过，`mdcheck`（可选） 照样报断链。**判据是这条引用要不要给人跟着走**：

- **真指针**（「打法菜单见 X skill 的某文件」）→ 按**引用文件自己的位置**写相对路径：`skills/A/references/x.md` 引 B 写 `../../B/...`；`../SKILL.md` 引 B 写 `../B/...`。写成 `B/...` 必被判断
- **素材类档案最容易欠账，而且一欠一批**（2026-10-16 九型库实战：251 个 md／50 处）：写案例正文时是**站在素材库的视角**抄路径的（`characters/x.md`、「人物/y.md」、`故事设定集/…`），在素材库里读着顺，换个库解析全断；同一批角色档抄同一张素材表，一处错就复制成几十处。**分三类落**：① 同库内 → 相对路径（`../label-systems/…`）；② **跨 skill 真指针 → `skills/<库名>/…`**（本仓惯例，`mdcheck` 与 `fix_md_links` 两个扫描器都认这种根相对形态，比数 `../../../` 稳）；③ 目标在 `archive/`、`workspace/records/` 等非 skill 目录 → 根相对路径（`archive/xueling/…`）。**「只是提一嘴」的素材名**才保持描述形态——判据仍是「读者要不要跟着走」。
- **通配名（`…NN_*-剧情整理.md`、`case-study-*.md`）写不出可解析目标**：它们是「一组真实存在的档」，硬凑成单个路径是错的。改成**可走的目录 + 描述**（`skills/X/stories/角色/整理/` 各章 NN 档），人照样能到、扫描器也不再欠账。
- **只是提一嘴**的素材来源名（`workspace/...`、别的库名）→ 保持描述形态，别硬凑路径

## 外部根补全：引用指向库外档案时怎么批量改（C2／C4）


断链里很大一批不是「文件没了」，是**目标在库外根下、而引用写成了裸相对路径**：

| 引用写法 | 真身 |
|:--|:--|
| 「事件时间线/查证材料-x.md」 | `workspace/records/<档案>/事件时间线/查证材料-x.md` |
| 「战报.md」 | `downloads/<事件>-快照/<节点>/战报.md` |
| 「20-文案集/10-趣味普查.md」 | `repos/<独立仓>/20-文案集/10-趣味普查.md` |

补全成**根相对路径**即可收工——两个扫描器都认这种跨库形态，`fix_md_links` 直接归到「跨库（合法）」不再报。一个 skill 一批，改完复跑 `--check`：

1. **定根**：按 ref 首段去对哪个外部根（`workspace/records/<档案>/`、`downloads/<事件>/`、`repos/<仓>/`）。同一批引用往往同根，先定根再动，别逐条试。
2. **根内按 basename 建索引**：命中唯一 → 换成 `根相对路径`。
3. **多候选用引用自带的目录段二次筛**：「Steam商店页/战报.md」 只对 `…/Steam商店页/` 那份；「要点提取.md」 有 2 份就**原样留着登记，不猜**——猜错等于把「哪一天的快照」改错，比断着更糟。
4. **叙述性提及不是引用**：正文里讲「目标仓库有 「.identity.md」」「上游的 CONTRIBUTING.md」是在说别人家的事——去反引号写成散文本；给它编一个本地路径才是制造错误。

**次序**：先把这档（路径写错／改名搬迁）啃完，再回头判「真缺」。前两档机械可批量、一趟消大半，剩下的一小撮才值得逐条判补档还是删引。

## 批量修断链：路径让脚本算，别手数层数


零星几处可以手改；**上到几十处（实测 141 个文件／148 处）就必须脚本化**，四条做法：

1. **按 basename 全库唯一定位真目标，再用 `os.path.relpath(目标, os.path.dirname(当前文件))` 算出该写的相对路径**。手数 `../` 在 4–5 层深的文件上必错，而且同类文件深度不一（同一个「规范档」被 2 层和 5 层深的产物各引一次），照抄邻档写法会连错一片。找不到唯一目标的（库外引用、占位名、重名 basename）**原样跳过并列出来人工判**，别硬凑一个路径。
2. **分两轮跑，别跑一轮就宣布干净**：第一轮只处理**裸文件名**引用（正则排除含 `/` 的），第二轮再处理**带路径**的（`../cases/x.md`、`skills/A/…`）——第一轮的正则看不到带路径那批，跑完一轮收工＝漏一片。每轮都拿 `fix_md_links.py --check` ＋ `mdcheck`（可选） 复核。
3. **反面教材与示例行要排除在替换之外**：正文里当坏例子写的 `characters/x.md`（教人别这么写）被脚本改成真路径，就失去了示范意义——替换前看上下文，含「别写」「形如」这类字样的行跳过或用尖括号占位。
4. **批量产物（组档／索引／速查表）里的引用写法，要连着生成器一起改**：只修产物不动模板，下次重建长回来；只改模板不重跑，存量还带旧毛病。两头都动的细则见 `environment-hygiene` 铁律「生成物两头都要改」。

## 泛化占位名与示例路径别用反引号


「_template.md」 这类「每个类目各有一份」的名字，反引号包起来会被当路径解析、判断链，而且**没有唯一真解可修**（全库有 N 份）。做法：去反引号写成散文本（「各类目文件夹内的 _template.md」），或写死一个真实存在的实例路径（「memes/表情包/_template.md」）。

**说明文字里的示例路径同样是引用面。** 写规范、示例、拆分记录时随手举的例子（形如 `references/<档名>.md`、裸文件名这类），会被扫描器当真引用解析，从当前文件所在目录一 resolve 就是断链——一次整理能为此欠上好几条新账，而它们其实是「举例」不是「引用」。做法：示例一律用尖括号占位（`references/<新档>.md`，`<…>` 在脚本内置排除表里），或干脆写成散文本。判据：**这个字符串是给人看的例子，还是给人跟着走的指针**——前者别带反引号，后者必须写全。

**索引／速查表／拆分记录里指向真档，一律写全路径。** 「挪到 `<档名>.md`」这种裸文件名，读者和扫描器都得先猜它在哪个目录，从别处解析必断。两套基准各归各：`../SKILL.md` 引自己库内写 `references/<档名>.md`；`references/` 引别的 skill 写 `../../<skill>/references/<档名>.md`。

## 内容重复也是引用链问题：单点真源 + 指针


同一条规则/口径被抄进 3+ 个文件时（不同 skill 的 SKILL.md、档案母档、附录各一份），改一处，其余立即漂移。做法：**留承载场景最全的那份写全量，其余压成「一句规则 + 相对路径指针」**，指针句里写明「别在这儿重抄一遍」（不写这句，下轮又会被抄回去）。删掉重复段后记得重跑体检——减少行数同时不影响链接完整性。

两条判据：

- **措辞不同、语义同一也算重复**——不要因为「不是逐字相同」就判断为两条规矩（典型：「四条硬红线」在核心档与复核档各一张表，条目一一对应）。判重的单位是**规矩**，不是字符串。
- **定权威方**：承载场景最全的、或口径更晚更严的那份作正本；份量相当的取「谁被执行时真会打开」。**两处口径打架时只留一套，并在被降级的一侧加边界注**说明归口——两处并存等于下一轮照旧口径做，白改。

## 让 CLI 按稳定 ID 找路径，而不是按目录名


改目录名会连带打断所有「拼目录名」的脚本（`<库根>/<旧目录名>/` 这种）。**把定位函数改成按稳定 ID 扫描目录**——正则从目录名里抠出那个不变的标识（编号/日期+序号），并对旧命名留一条回退分支。这样改名不影响任何命令，回滚也不会卡住。

规矩提前立：**第一次做改名/分层重构，就把定位函数写成「认 ID 不认路径」**；等脚本散落了一堆路径拼接再回头改，成本和风险都翻倍。同理，新增/删除文件后要给一个「扫全库对账」的命令（状态/体检），而不是靠人记哪些文件还在。
